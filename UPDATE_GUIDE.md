# Repository Update Guide

This guide explains how to maintain the public Ciforus information repository.

## Purpose

This repository is a public transparency and documentation hub.

It should stay:

- structured
- factual
- calm
- professional
- easy to review

It should not become:

- a marketing page
- a code dump
- a place for private implementation details
- a source of hype language

## Update Rules

Update the repository when there are meaningful changes, such as:

- official website links are finalized
- whitepaper or litepaper files are updated
- audit link changes
- token utility details are finalized
- tokenomics details change
- roadmap milestones become public
- product modules launch or change materially

Avoid excessive small edits that create noise without improving clarity.

## Before Each Update

Check:

1. Is this fact public and approved?
2. Is the wording neutral and factual?
3. Does it avoid hype or financial promises?
4. Does it avoid sensitive technical details?
5. Does the token remain connected to the product ecosystem?
6. Are links still official and correct?

## Recommended Commit Style

Use clear, calm commit messages:

- `Update official links`
- `Add final litepaper reference`
- `Refresh tokenomics summary`
- `Add public roadmap note`
- `Update audit resource link`

Avoid promotional commit messages.

## Suggested Future Additions

Only add these when they become useful and public-ready:

- `docs/roadmap.md`
- `docs/glossary.md`
- `docs/review-checklist.md`
- `resources/pitch-deck.md`
- `.github/ISSUE_TEMPLATE/question.md`

## Issue and Discussion Settings

Early phase recommendation:

- Issues: off
- Discussions: off
- Wiki: off
- Projects: off

Later, GitHub Discussions can be enabled if the repository becomes a serious technical or public Q&A surface.
